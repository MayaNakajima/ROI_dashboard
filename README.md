# マーケティング ROI ダッシュボード

ONWARD Marketing マーケティング本部の、事業部別・月次KPIを一元管理する **HTML単一ファイル** のダッシュボードです。バックエンドを持たず、ブラウザ上で動作します。本リポジトリは、従来ローカルフォルダ（`Downloads\05_ROIダッシュボード`）で管理していたアプリを、GitHubでの開発に移行するために構成したものです。

---

## 1. アプリ概要

- **形式**: HTML単一ファイル（バックエンドなし）。BOXに格納して複数人で共有利用する運用を想定。
- **対象組織**: マーケティング本部（ALL・独自KPI） / UN（企業ユニフォーム） / SCH（スクール） / MED（メディカル） / IS（インサイトセールス）
- **主要機能**: 表示期間フィルター、MQL進捗（目標達成率）、コンバージョンファネル（MQL→SAL→SQL→受注）、月次推移タブ（KPIテーブル・グラフ・コンテンツROI）、組織間比較テーブル、データ永続化（localStorage + JSONエクスポート/インポート）、Excel一括取込。
- **技術**: Chart.js 4.4.0 / SheetJS(xlsx) 0.18.5 / chartjs-plugin-datalabels 2.0.0（いずれもcdnjsから読込）。
- **localStorageキー**: `mktg_roi_v4`
- **年度定義**: 3月〜翌年2月（例：2026年度 = 2026-03〜2027-02）

詳細仕様（データモデル・Excel列マッピング・重複除外ロジック等）は `docs/` 配下の引き継ぎ資料を参照してください。

## 2. リポジトリ構成

```

```

## 3. 個人情報の取り扱い（重要）

元フォルダの以下のファイルは **個人情報・顧客データ（メールアドレス・氏名・顧客一覧・企業情報など）を含むため、本リポジトリには格納していません**。`.gitignore` にも登録済みで、誤ってコミットされないようにしています。

- 実績ファイル：`マーケティング本部｜IS｜実績.xlsm` / `MED` / `SCH` / `UN` / `UN｜実績_02.xlsm` / `.xlsx`
- `ユーザーリスト.xlsx` / `売上計上全ユーザーリスト.xlsx` / `売上計上全ユーザーリスト｜LBC付与｜*.xlsx`
- `trans_*.xlsx`（顧客企業データ） / `test｜売上データ分析_ABM×LTV.xlsx`（顧客プロファイル）

これらはアプリの「BOXファイル取込／Excel取込」機能で **実行時に手動インポートする元データ** です。開発・動作確認の際は、元フォルダまたはBOXから該当ファイルを取得してインポートしてください（リポジトリには置かないこと）。

## 4. ローカルでの動作確認

`marketing-roi-dashboard.html` をブラウザで開くだけで動作します（ローカルサーバー不要）。データは `localStorage`（キー `mktg_roi_v4`）に保存されます。過去データは `data/` のJSONを「インポート」から読み込めます。

## 5. Git 開発フロー（このリポジトリの運用ルール）

開発は必ず **作業ブランチ** で行い、mainへは **マージコミット** で取り込みます。手順は次のとおりです。

### 5-1. 作業ブランチを切る

作業内容がわかるブランチ名を付けます（例：`feature/`, `fix/`）。

```bash
git switch -c feature/作業内容がわかる名前
```

### 5-2. 作業してコミットする（作業内容はコメントに残す）

変更をステージしてコミットします。**コミットメッセージに作業内容を必ず記載**します（1行目に要約、必要に応じ本文で詳細）。

```bash
git add <変更したファイル>
git commit -m "feat: 〇〇を追加" -m "・変更点1 ・変更点2 ・意図/背景"
```

区切りのよい単位でこまめにコミットしてください。1つのブランチに複数コミットして構いません。

### 5-3. マージ前に確認する

mainへ取り込む前に、必ず内容を確認します。

```bash
git status                 # 作業ツリーがクリーンか
git log --oneline -10      # コミット内容の確認
git diff main...HEAD       # mainとの差分を確認
```

確認観点の例：意図しないファイルが含まれていないか、**個人情報を含むファイルが混入していないか**（下記コマンドで確認）、動作確認は済んでいるか。

```bash
# 追跡対象にメールアドレスが含まれていないかチェック（何も出なければOK）
git grep -I -n -E "[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}"
```

### 5-4. 確認OKならマージコミットする

`--no-ff` を付けて、履歴にマージコミットを残します（ブランチでの作業単位が履歴に残ります）。

```bash
git switch main
git merge --no-ff feature/作業内容がわかる名前 -m "Merge branch 'feature/作業内容がわかる名前': 〇〇"
```

### 5-5. リモート（GitHub）へ反映する

```bash
git push -u origin main
```

> リモートは `origin = https://github.com/MayaNakajima/ROI_dashboard.git` に設定済みです。初回pushでは認証（GitHubのユーザー名 / Personal Access Token）が必要です。

## 6. 移行の完了状況と残タスク

移行は **マージコミットまで完了済み** です。現在のmainの履歴は次のとおりです。

```
*   Merge branch 'feature/migrate-roi-dashboard': ROIダッシュボードプロジェクトを移行   <- main
|\
| * chore: 個人情報を含まない管理用Excelを追加
| * docs: 引き継ぎ書(README)と関連ドキュメントを追加
| * feat: ROIダッシュボードアプリ本体と保存データを移行
|/
* chore: リポジトリ初期化（.gitignore追加）
```

作業ブランチ `feature/migrate-roi-dashboard` を切り、3コミット（作業内容をコメント記載）した上で、`--no-ff` で main へマージしています。

### 残タスク（Windows上で1回だけ実施）

この移行作業は同期フォルダ上で行われた関係で、gitのロックファイルや一時ファイルがフォルダに残っています（同期フォルダ側の制約で作業環境からは削除できませんでした）。**Windows上で `setup_git.bat` を1回実行して後始末してください。**

`setup_git.bat` が行うこと：

1. 残存ロックファイル（`.git\*.lock` 等）・一時ファイル（`_deltest.txt`／`_addtest.txt`）・テスト用ゴミの削除
2. 移行作業で作成した一時ブランチ `_locktest` の削除
3. ブランチ・コミット履歴・作業ツリー状態の表示（クリーンであることの確認）

実行方法：エクスプローラーで `setup_git.bat` をダブルクリック、またはこのフォルダで `setup_git.bat` を実行します。この後始末をしないと、次回のコミット/pushでロックファイルが原因のエラーが出ることがあります。

後始末後、GitHubへ反映するには次を実行してください。

```bat
git push -u origin main
```
