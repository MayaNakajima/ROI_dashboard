## 成果物
`marketing-roi-dashboard.html`（添付）

## ダッシュボード概要

対象組織：マーケティング本部 / UN（企業ユニフォーム）/ SCH（スクール）/ MED（メディカル）/ IS（インサイトセールス）
※ マーケティング本部（ALL）は現在データなし

### 主要機能
- **表示期間フィルター**：開始・終了の2つの年月で期間指定
- **MQL進捗**：年間・期間累計・前年度/当年度別の目標達成率
- **コンバージョンファネル**：MQL→SAL→SQL→受注の累計と転換率
- **月次推移タブ**：数・単価・引き上がり率の月別テーブル＋グラフ
- **コンテンツROI**：予算÷制作本数を月別・組織別で表示
- **組織間比較テーブル**：期間集計での組織横断比較
- **月次グラフ**：CPA・セッション/MQL・費用・転換率・目標比較
- **月次データ入力テーブル**：手動入力対応
- **目標設定**：セッション(MAL)・MQL・SQLの月次目標を組織・年度別に設定（年間均等配分ボタンあり）
- **データ永続化**：localStorage（キー：`mktg_roi_v4`）＋JSONエクスポート/インポート（BOX共有用）

## 技術仕様

- 純粋なHTML/JS単一ファイル（バックエンドなし）
- Chart.js 4.4.0、chartjs-plugin-datalabels 2.0.0、SheetJS/xlsx 0.18.5（cdnjs）
- localStorageキー：`mktg_roi_v4`

### データモデル（`appData`）

```
actuals[org][YYYY-MM] = {
  sessions,           // セッション数（MAL）※予実管理Row4から取得
  cv,                 // MQL数（実績ファイルB列CVフラグをC列CV日時の月で集計）
  sal,                // SAL数（実績ファイルR列col[17]のSAL日付の月で集計）
  sql,                // SQL数（実績ファイルS列col[18]のSQL日付の月で集計。ISはS列orT列）
  jucyu,              // 受注数（実績ファイルT列col[19]／ISはU列col[20]の受注日付の月で集計）
  cost_items[8],      // 費用①〜⑧（予実管理Row30〜37）
  cost_content,       // コンテンツ費用（単価×本数で自動計算）
  content_count,      // コンテンツ制作本数
  mql_by_channel{},   // チャネル別MQL数（実績ファイルH列から。空白=不明/Unknown）
  cv_by_type{}        // CV種別MQL数（実績ファイルB列から3分類）
}
// ★MQL/SAL/SQL/受注は実績4ファイルから直接カウント（実績ファイルが権威）。
//   予実管理からはsessions(MAL)・cost_items・targetsのみ取得し、実績行は取込まない。

targets[org][YYYY] = {
  monthly_mql[12],      // MQL月次目標（予実管理Row15）
  monthly_session[12],  // セッション月次目標（予実管理Row13）
  monthly_sql[12]       // SQL月次目標（予実管理Row22）
}

costLabels[8]  // 費用項目名（デフォルト：コラム/メルマガ/WP/事例/広告/Web運用/コンサル/その他）
```

チャネルキー（10種）：Organic / Paid / Display / Email / Direct / Referral / OrganicSocial / Offline / Other / Unknown（不明＝H列が空白）
CV種別キー（3種）：inquiry（問い合わせ系）/ service_dl（資料ダウンロード系）/ wp_dl（WP系）

### 表示期間
- 年度定義：3月〜翌年2月
- デフォルト：当年度3月〜当月
- KPI比較：選択期間 vs 1年前の同期間

## Excelファイル取込仕様

### ① 実績ファイル（.xlsm）― 組織ごとに4ファイル

シート名：
- UN → `流入チャネル別顧客一覧_7月以降完全ユニークではない`
- SCH/MED/IS → `流入チャネル別顧客一覧_ユニーク`

1行目＝見出し（ヘッダー行）。ヘッダー名でカラムを検索し、固定インデックスはフォールバック。

| 列（0始まり） | 内容 | 用途（★=実績ファイルから直接カウント） |
|---|---|---|
| col[1]（B列） | CVフラグ | ★MQLとしてカウント＋3分類（問い合わせ/資料DL/WP）。値があれば1MQL |
| col[2]（C列） | CV日時（回答日時, datetime） | ★MQLの月キー（YYYY-MM） |
| col[7]（H列） | 流入チャネル | ★mql_by_channelの分類。**空白は不明（Unknown）としてカウント** |
| col[17]（R列） | SAL datetime | ★**SALをこの日付の月でカウント** |
| col[18]（S列） | SQL（IS以外）/ SQL1（IS） | ★**SQLをこの日付の月でカウント**（ISはS列/T列いずれか） |
| col[19]（T列） | 受注（IS以外）/ SQL2（IS） | ★受注をこの日付の月でカウント（IS以外）。ISはSQL2の日付 |
| col[20]（U列） | 受注（ISのみ） | ★受注をこの日付の月でカウント（ISのみ） |

- **MQL/SAL/SQL/受注は各ステージの日付列の月で集計**（各指標は発生月に計上。MQL月と後続ステージ月は異なりうる）
- MQLの月＝C列（CV日時）、SALの月＝R列、SQLの月＝S列（ISはS列優先、無ければT列）、受注の月＝T列（ISはU列）
- ISのSQL：col[18]またはcol[19]いずれかに日付があれば1カウント（日付のある列の月に計上）
- ISの受注はU列(col[20])のみ（T列col[19]はSQL2なので受注に計上しない）

★重要（日付の混在形式）：SAL/SQL/受注列の日付は「日付データ」と「日付書式が外れた数値シリアル（例:46174=2026-06）」が混在する。getDateYMは Date / 数値(>40000のExcelシリアル) / 文字列(YYYY-MM等) の3形式すべてを月に変換する。datetime形式のみを拾う実装だと数値シリアル分を取りこぼし大きくズレる（例：IS SALが32→本来52）。全角スペース'　'等は日付として扱わずスキップ。
★再取込時は該当組織のMQL/SAL/SQL/受注・チャネル・CV種別を一旦0クリアしてから実績ファイルの値を格納（古い取込値の混入防止）。

流入チャネル値→キー変換：
| 実際の値 | キー |
|---|---|
| organic | Organic |
| case, column | Organic |
| listing | Paid |
| display | Display |
| mail | Email |
| direct | Direct |
| link | Referral |
| others | Other |
| （空白） | Unknown（不明） |

CVフラグ値→CV種別変換（3分類。判定はWP→資料DL→問い合わせの順）：
| 種別 | パターン（含む文字列） |
|---|---|
| ③ wp_dl（WP系） | WP、ホワイトペーパー、お役立ち資料、WPダウンロード、\|WP1、\|WP2 |
| ② service_dl（資料ダウンロード系） | 資料DL、サービス資料、会社案内、カタログ、総合カタログ、資料ダウンロードフォーム |
| ① inquiry（問い合わせ系） | お問合せ・ご相談、問い合わせ など（上記以外すべて） |

### ② 予実管理ファイル（.xlsx）― 4シート構成

シート名マッピング：オリジナルユニフォーム→UN / スクール→SCH / メディカル→MED / インサイトセールス→IS

| 行（0始まり） | Excelの行番号 | 内容 |
|---|---|---|
| rows[1] | 2行目 | 年度ラベル（YYYY年度） |
| rows[2] | 3行目 | 月ヘッダー（3月〜2月）※2024年度=テキスト、2025/2026年度=datetime |
| rows[3] | 4行目 | セッション実績（MAL）★取込む |
| rows[4] | 5行目 | MQL（CV）実績 ― ※取込まない（実績ファイルを使用） |
| rows[6] | 7行目 | SAL実績 ― ※取込まない（実績ファイルを使用） |
| rows[8] | 9行目 | SQL実績 ― ※取込まない（実績ファイルを使用） |
| rows[10] | 11行目 | 受注実績 ― ※取込まない（実績ファイルを使用） |
| rows[12] | 13行目 | MAL目標（セッション）★取込む |
| rows[14] | 15行目 | MQL目標 ★取込む |
| rows[21] | 22行目 | SQL目標 ★取込む |
| rows[29〜36] | 30〜37行目 | 費用①〜⑧（コラム/メルマガ/WP/事例/広告/Web運用/コンサル/その他）★取込む |

※ 予実管理から取込むのは **セッション(MAL)実績・費用8項目・目標(MAL/MQL/SQL)** のみ。
　 MQL/SAL/SQL/受注の実績値は実績ファイルからのカウントを使用し、予実管理の該当行は取込まない。

月列マッピング（buildColYMMap関数）：
- 2024年度：col[1〜12]にテキスト「3月」〜「2月」→fyStartsから年を特定してYYYY-MMに変換
- 2025/2026年度：col[13〜24]、col[25〜34]にdatetimeオブジェクト→xlDateToYM()で変換

### ③ コンテンツ本数管理ファイル（.xlsx）

シート：年度（例：「2026」）またはコンテンツ管理という名のシートを自動検出

| 列 | 内容 |
|---|---|
| col[0]（A列） | 制作種別（コラム記事・ホワイトペーパー等） — 空白時は上の行から継承 |
| col[1]（B列） | 事業部 — 空白時は上の行から継承 |
| col[2]（C列） | 詳細（ライター種別テキスト。「合計本数」「合計額」を含む行はスキップ） |
| col[3]（D列） | **単価**（費用計算に使用） |
| col[5〜16]（F〜Q列） | 月別制作本数（3月〜2月） |

- 費用 = 単価 × 月別本数 で自動計算
- 事業部マッピング：メディカル/メディカル事業部→MED / インサイトセールス/IS/IS事業部→IS / 企業U/企業ユニフォーム/ユニフォーム→UN / 学生服/スクール→SCH

## タブ構成

| タブ | 内容 |
|---|---|
| 📈 ダッシュボード | KPIカード・MQL進捗・ファネル・チャート・組織比較 |
| 📊 月次推移 | 月別KPIテーブル（数・達成率・引き上がり率・単価）・転換率グラフ・コンテンツROI |
| 📝 データ入力 | 月次データ手動入力・編集 |
| 🎯 目標設定 | MAL/MQL/SQLの月次目標設定（組織×年度）。年間合計入力→「均等配分」ボタンで月次12等分 |

全タブに表示期間フィルター（開始年月・終了年月）が表示される。

## データ優先順位（データソース）

指標ごとの権威データ：
- cv（MQL）/ sal / sql / jucyu（受注）→ **実績ファイルが権威**（各ステージの日付列の月でカウント）
- mql_by_channel / cv_by_type → **実績ファイルのみ**
- sessions（MAL）/ cost_items（費用8項目）/ targets（MAL/MQL/SQL目標）→ **予実管理が権威**
- cost_content / content_count → **コンテンツ本数管理ファイル**

doAutoImport の処理順：①実績ファイル読込（cv/sal/sql/jucyu/mql_by_channel/cv_type を格納）→ ②予実管理読込（sessions/cost_items/targets のみ適用。cv/sal/sql/jucyu は上書きしない）→ ③コンテンツ本数管理読込（cost_content/content_count を追加）

※ 参考として、予実管理のMQL実績と実績ファイル集計値に差分があればコンソールに出力するが、採用値は常に実績ファイル側。

## CPA定義

```
CPA = 期間合計費用（cost_items合計 + cost_content） ÷ 期間合計MQL数
```

## 現在の課題・検討事項

- BOXにHTMLを格納して複数人で使う運用を想定
- データ共有はJSONエクスポート → BOX保存 → 他ユーザーがインポートの手順
- コスト項目名（費用①〜⑧）は現在デフォルト名。将来的に予実管理ファイルのRow30〜37の行ラベルを読み込んで自動命名する改善余地あり
- マーケティング本部（ALLタブ）は組織別データの合算表示のため、個別データ取込後に反映される
- 実績ファイルはUNのみシート名が異なる点に注意（7月以降完全ユニークではない）
